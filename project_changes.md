# История изменений проекта (Changelog)

## [2026-09-08]

### Улучшения интерфейса, безопасности и логирования (`api.php`, `index.html`)
1. **Точечное сохранение расписания по дням (`save_day`):**
   * Переход от сохранения всей недели целиком к сохранению исключительно измененного дня (`save_day`). Это предотвращает гонки данных (race conditions) при одновременном редактировании одного ученика несколькими пользователями.
2. **Расширенное логирование расписания в `logs`:**
   * При сохранении дня в таблицу `logs` записывается тип события `schedule`, ID пользователя (`user_id`), а также полный JSON-снимок сохраненных данных дня в `event_message`.
3. **Очистка данных при выходе из системы (`logout`):**
   * При logout дополнительно сбрасывается поисковый запрос (`studentQuery`) и закрывается выпадающий список учеников.
4. **Интерфейсные улучшения инпутов и мобильной адаптивности (iOS Safari):**
   * В поле выбора ученика добавлен крестик (кнопка очищения) справа.
   * Текст и плейсхолдер инпута выбора ученика теперь реактивно меняют цвет в соответствии с текущей темой.
   * Время ухода (`input[type="time"]`) оптимизировано для корректного отображения на iPhone в Safari (предотвращен вылет за пределы блока), а правая иконка часов стилизована под цвет левой.
5. **Ограничение для роли Родителя (роль 2):**
   * На вкладке «Расписание ученика» прошедшие дни автоматически блюрятся (`blur`) и блокируются для редактирования.

   * **Администратор (роль 0):** полный доступ ко всем разделам и справочникам.

## [2026-09-01]

### Изменения в бэкенде и архитектуре данных (`api.php`)
1. **Отключение дебага:**
   * Удалено сохранение отладочного файла `debug_save.txt` при вызове эндпоинта сохранения расписания (`save_week`).
2. **Отказ от таблицы `schedules` (JSON кэша):**
   * Полностью удалена зависимость от таблицы `schedules`. Эндпоинты `get_week` и `save_week` переведены на работу исключительно с реляционной таблицей `student_schedules`.
3. **Поддержка кружков в `student_schedules`, хранение по ID и мягкое удаление (`deteled`):**
   * Добавлена колонка `clubs` (тип `TEXT`) в таблицу `student_schedules` для хранения выбранных кружков в формате JSON-массива идентификаторов (`id`).
   * Поддержан столбец мягкого удаления `deteled` в таблице `clubs`: удаление кружка выполняет `UPDATE clubs SET deteled = 1`, сохраняя целостность исторических данных расписания.
4. **Логирование добавления и удаления кружков в `logs`:**
   * В эндпоинты `add_club` и `delete_club` добавлена запись событий в системную таблицу `logs` (тип события `clubs`), аналогично логированию учеников.

4. **Исправление маппинга номеров недель (`weeksMap`):**
   * Добавлена функция согласования идентификаторов недель фронтенда (локальных ID недель от 1 до 21) и номеров ISO-недель бэкенда (`week_num`), благодаря чему вкладки «Расписание ученика» и «Сводная матрица» корректно отображают и сохраняют данные из таблицы `student_schedules`.

### Изменения в интерфейсе и печати (`index.html`)
1. **Устранение пустых страниц при печати:**
   * В `@media print` стили добавлены правила сброса высоты для `html` и `body` (`height: auto !important; min-height: 0 !important; overflow: visible !important`), а также для `#print-container`, что предотвращает появление лишних пустых листов в конце печатного документа.
2. **Унификация размеров кнопок в шапке:**
   * Кнопки переключения темы, авторизации (входа) и сохранения приведены к единому стандарту фиксированного размера (`w-9 h-9 flex items-center justify-center rounded-xl`), обеспечивая одинаковые габариты и выравнивание иконок.
3. **Автоматический выбор текущей или следующей недели и привязка `<select>`:**
   * Устранена специфика работы Alpine.js с динамическими `<option>` внутри `<template x-for>`: добавлено явное связывание `:selected="week.id === selectedWeek"`, благодаря чему выпадающий список недель в шапке сайта при загрузке корректно отображает текущую неделю («31 авг - 4 сен»), а не первый элемент списка.
12. **Устранение двойного срабатывания автосохранения:**
   * Из textarea для комментариев удален лишний триггер `@blur="autoSave()"` (так как `@change` уже отрабатывает изменение), а в метод `autoSave()` добавлен механизм дебаунса (`setTimeout`/`clearTimeout` на 400мс). Теперь при вводе данных сетевой запрос `save_week` отправляется строго 1 раз.
9. **Унификация идентификаторов недель с ISO номерами (устранение дублирования):**
   * Идентификаторы недель (`id`) во фронтенде (`index.html`) и переменные `selectedWeek` / `selectedWeekNum` теперь напрямую равны номерам ISO-недель (например, `36`).
   * На бэкенде (`api.php`) полностью убраны вспомогательные таблицы маппинга (`getWeeksMap`): эндпоинты `get_week` и `save_week` работают напрямую с номером ISO-недели как с ключом. Ответы в Network стали абсолютно чистыми, без какого-либо дублирования данных.
3. **Переход на Production сборку Tailwind CSS и локальные библиотеки:**
   * Удалено предупреждение из консоли браузера о недопустимости использования `cdn.tailwindcss.com` в production.
   * Настроен Tailwind CLI (`@tailwindcss/cli`), добавлены конфигурационный файл `tailwind.config.js`, исходные стили `src/input.css` и скомпилированный минифицированный файл `dist/output.css`, подключенный в `index.html`. Добавлены NPM-скрипты сборки (`npm run build:css` и `npm run watch:css`).
   * Библиотеки **Alpine.js** и **FontAwesome** (включая шрифты `.woff2`) скачаны и перенесены в локальную директорию проекта `vendor/` для полной автономности (без внешних CDN).
